## 修复:角色浮窗对内联头像不触发(raid-buff-debuff.html#content_1_3)
- 现象:`<img alt="花のチルカ_icon.png" src="/img/f5e66528225fecf8.png">` 不触发 `.mirror-content img[data-char]` 浮窗。
- 根因:`tagAvatars`(site/.vitepress/theme/components/MirrorContent.vue)只靠 `avatarMap[src的hash]`,而 `avatarHashes`(charRefs.json)只由角色 JSON 的 `icon` 字段(角色一览缩略图 hash)构建。wiki 正文内联头像用了**另一个 hash**(`f5e66528225fecf8.png` vs 一览的 `e76ea3ae1039aae9.png`),该 hash 未进映射→漏掉。
- 修法:`tagAvatars` 增加兜底——`avatarMap` 未命中时,用 img 的 `alt`/`title`(形如 `花のチルカ_icon.png`,去掉 `_icon`+扩展名得角色名)经 `nameAliases` 回 key 设 `data-char`。alt 来自原 wiki HTML 日文文件名,翻译不改,zh/ja 页均可用。仅在 `_icon`/图像扩展名且名字匹配真实角色时触发,避免误伤非头像图。
- 排查范围(静态扫 frag):**838 张头像 img / 745 个 frag 页**有同类问题(含 raid*/annihilation/bedroom-scenes/scenario-order/artists/几乎所有 characters/*),一次性全修。
- 验证:`vitepress build` 通过(dist OK,5313 文件)。提交 bc5b2ac。未推送(用户本次未指令 push)。
- 注:URL 形态坑——内联头像 URL 的 bytehex 被截断/乱(如 `381AEE38381E383ABE382AB5F...` 解不出全名),故**不能靠 URL 解析补 avatarHashes**,只能靠 alt 兜底。

## 修复:浮窗盖住鼠标/越界(定位规则重写)
- 现象:之前 `placeHover`(CharHoverModal.vue)只用锚点矩形(a.left/right/top/bottom)定位,**完全没用鼠标坐标**,所以"右侧放不下→放下方/贴左缘"仍可能落在光标上;用户指出应按"固定宽~750、鼠标在(1900,800)右缘时浮窗放左侧、光标在(1900,450)偏右时右边留400"的简单模型。
- 修法:锚点 anchor 现带 `mx/my`(onOver 传 `e.clientX/Y`;HoverAnchor 接口加 mx/my 字段)。`placeHover` 重写为极简确定规则:①锚点在鼠标左且「锚点右缘→鼠标左缘」间隙≥10+W→放右侧;②锚点在鼠标右且反向间隙够→放左侧(均保证光标在浮窗外);③间隙不够→鼠标偏左放右侧/偏右放左侧(光标另一侧,必不遮);④垂直取 min(a.top,my)对齐并夹回视口。最终 left 再 clamp 进 [pad, vw-pad-W]。核心保证:光标 x 永不在 [left,left+W],且不越界。
- 验证:vitepress build 通过(dist OK)。提交(本次)。未推送。
