# 2026-08-11 链接方案重设计（句末【】标签）

## 背景
用户决定重做 zh 镜像站正文超链接逻辑：旧方案（link_terms.yaml 的 zh 精确匹配 + 句中切割注入）把译文搞乱（译名不一致即丢链/错位、切割破坏译文结构）。

## 新方案（用户定）
- 不在句子中间切割注入链接，而是在中文译文**句末**追加 `翻译文本【名称1】【名称2】` 标签。
- 链接数据**跟日文原页的 `<a>` 保持一致**：渲染时读取日文原页正文 `<a>`（href + 日文文本），直接在每个块末拼链接标签。跳转绑定**原日文 href**，不依赖中文名匹配 → 译名不准也不影响跳转。
- 显示名用 glossary 中文译名（优先 names → skills → terms → high_freq），查不到兜底日文原文。
- **表格特例**：单元格纯文本恰为单链接词（原文就只有这个词）→ 直接 `【名称】`（不带括号外译文，因单元格文本本身就是译文）；单元格是句子 → 用 `翻译文本【名称】`。

## 实现（pipeline/escah_pipeline/i18n.py）
- 新增 `_link_display_zh(ja)`：统一 glossary 查显示名。
- 提取 `_normalize_link_href`（原 render_locale 闭包 `_normalize_href`，已废弃的 `_apply_config_links` 不再调用）。
- 重写 `render_locale`：
  - 渲染前解析模板，收集正文 `<a>`（href+ja_text）按 `_BLK_ATTR` 祖先归属到 `block_links[bid]`，不在块内的进 `top_links`；随后 `drop_tag()` 去掉所有 `<a>` 壳（链接改句末）。
  - 块级回退：用 `block_links[bid]` 在 blk_zh 末追加 `【名称】`（class=escah-ilink）；表格特例单链接词直接 `【名称】`。
  - 节点级 `_sub`：对 `top_links` 中 ja_text 出现在 key["ja"] 的，在该 key 中文末追加 `【名称】`。
  - 例外页（SKIP_LINK_SLUGS artists/voice-actors）：日文原文 + 句末【日文名】。
- 前端 `custom.css` 新增 `.mirror-content a.escah-ilink` 样式（紫色小角标）。
- 旧 `_apply_config_links`/`_wrap_block_links`/`_fill_block_keep_links`/`_fill_block_ja_links` 已不再被主线调用（保留未删）。link_terms.yaml 仍被 extract 工具用，但渲染层不再依赖。

## 验证
- sync-site + build（NODE_OPTIONS=--max-old-space-size=8192 解决 OOM）成功。
- 全站 666 页：残留 `{{key}}` 0、空 `<a>` 壳 0；译文完整；11800 个 escah-ilink 句末标签。
- b-universe 12 BOSS 链接全中；faq 等重灾页译文未乱、多链接句子正确追加多标签。
- DENAI 等个别重复是忠实于日文原页（原句确有多个相同 `<a>`），非 bug。

## 已知待优化（用户确认是否处理）
- 部分链接显示名回退日文（`レイド`/`DENAI`/`エッチシーンを見る`/`こちら`/`開催中のイベント` 等）：glossary 无对应中文译名。对应站内页面的（如 レイド=团战）可补 glossary 显示中文；外链说明词（`こちら`=这里）显示日文可接受。
- 表格特例仅在"块级单链接词单元格"触发；节点级切分的表格单元格（多数）走"译文+句末标签"，少数略冗余但不破坏。

- SITE_VERSION 1.2.4→1.2.5；changelog.json 新增 1.2.5（用户视角）。commit b7a8252 → push main（f7ed652..b7a8252），CI 部署。

# 2026-08-11 下午：链接行为 + 正文注入三大回归修复

## 用户反馈（严厉）
1. 正文目录（TOC）改得无法跳转。
2. b-universe 评论内容乱入正文（很多处 `--[cnXXX]`、`plugin-tooltip` 残留），角色名被「注入替换」成 `<span class="char-ref" data-char>`。
3. 角色名没按「句末【链接】」方案，而是被注入。
4. 重申铁律：**翻译正文不得做任何注入效果**。

## 根因
- **TOC**：`_collect_links` 对页内锚点 `<a href="#...">`（目录 .contents 项）也 drop 了壳 → TOC 变纯文本无法点击。`_relink_toc` 标题文本匹配也因 anchor_super 残留符号（†）失败。
- **角色名注入**：sitegen `_neutralize_char_links` 把「<a href=characters/名.html>」改成 `<span data-char>`，i18n 收集不到链接源 → 不生成句末【链接】；客户端 `wrapPlainTextNames` 又对纯文本角色名注入 data-char。
- **评论区**：`wrapPlainTextNames` 没跳过 `.pcomment`，评论里角色名被注入。

## 修复（pipeline/escah_pipeline/i18n.py + sitegen.py + MirrorContent.vue）
- `_collect_links`：页内锚点 `<a href="#...">` 保留（不 drop）；新增收集 `<span data-char>` 作为角色链接源（href 规范化为 `/zh/characters/<名>.html`），drop 壳、句末【链接】。
- `_relink_toc`：标题文本去空白时剥离开头非文字符号（†）以匹配 TOC。
- `_normalize_link_href`：站内链接不再加 target（默认同标签，中键新标签）；外链原样。
- `_INTLINK_RE` 兜底段改为**清除**站内链接的 target/rel（而非补加）。
- **sitegen `_neutralize_char_links` 保持保留 `<a>`**（角色详情页真实存在，不 404）；但 render 仍从 `<span data-char>` 还原句末【链接】（兼容旧 i18n template）。
- **MirrorContent.vue**：`wrapPlainTextNames` acceptNode 跳过 `.pcomment`（评论区不注入）；`tagCharLinks` 跳过 `a.escah-ilink`；`onClick` 对 `a.escah-ilink` 放行跳转（hover 仍浮窗，不 pin）。

## 验证（sync-site + build 全站 666 页）
- escah-ilink 总数 1,102,173；`/characters/` 角色链接 11,291（全站角色名走句末【链接】）。
- **静态 data-char=0**（服务端不再注入正文）；空 `<a>` 壳=0；**TOC 无 `<a>` 的页面=0**（所有目录可跳）。
- 注意：改 i18n.py 链接收集逻辑后**必须重跑 sync-site 再 build**，否则 build 用旧 frag 缓存看不到改动（本次踩坑：先 build 没重跑 sync-site，dist 仍是旧态）。

# 2026-08-11 晚：角色名独立逻辑——句末【角色名】浮窗（不跳转）

## 用户决策
- 全页面（含评论区）正文里的角色名，无论原文有没有跳转链接，都在**块级 blk 末尾**追加 `【角色名】` 触发浮窗，**不跳转**。
- 角色这一块是**单独处理逻辑**，跟正常跳转超链接（escah-ilink）不一样。
- 原文本里的角色 `<a>` 跳转链接**降级**（去 href，不跳），浮窗统一转移到句末【角色名】。

## 实现
- **i18n.py render_locale**：链接源从二元组升级为三元组 `(href, ja_text, is_char)`；`_collect_link` 内 `is_char = href 含 characters/`；按 `is_char` 在块末/节点级输出 `class=char-ref`（无 href，不跳转）或 `escah-ilink`（跳转）。`_collect_link` 源头 per-bid 按 `(显示名,is_char)` 去重 + 生成处 `seen_links` 双保险，防同块同名双追加。`.plugin-tooltip` 内 `<span data-char>` 跳过不收集（由前端纯文本扫描兜底，避免重复）。
- **MirrorContent.vue**：原 `wrapPlainTextNames`（句中替换注入）重构为 `collectBlockCharTags`（按块收集纯文本角色名，块末追加 `【角色名】` char-ref 浮窗标签，原位不替换）；`tagCharLinks` 把残留角色 `<a>` 降级去 href；`acceptNode` 跳过 `[data-char]/.char-ref/脚本/样式/a`（含评论区，不再 FILTER_REJECT pcomment）。新增 `nameAliasesInv` 反向查 key→显示名。
- **custom.css**：`.mirror-content .char-ref` 改为浅描边胶囊（区别于 escah-ilink 紫色实心），hover 反色；dark 模式适配。

## 验证（sync-site + build 全站）
- b-universe：角色名全为 `<span class="char-ref" data-char=日文名>【中文名】</span>`（不跳转）；正常链接（超昂裝備/交換所/各 BOSS 页）仍为 `escah-ilink` 跳转。双追加消除（368/383 行从两个 span 降为一个）。
- buniv-001（评论/子页）：`魔女蕾雯`/`神骑迪亚罗鲁`/`节拍婚礼·千麻` 等全为 char-ref 句末浮窗标签，无乱入。
- `plugin-tooltip` 不再导致重复角色标签。

## 状态
- 仅本地改动（未提交/未推送）。
