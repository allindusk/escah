## 觉醒页三次修复（用户强刷+换浏览器仍不一致，真因定位）

### 真因：顶部跳转目录（key1-22）与正文标题（key23+）是两套独立 key，仅修正文标题漏了目录
- 用户看到的"正文目录"实际是 template 顶部 `list1` 跳转目录（`<a href="#content_*">{{key1}}…{{key22}}</a>`），**不是** h2/h3 标题。之前核对只看了 h2/h3（key23+），误判"已一致"。
- key19/21/22 的 zh 被**错填成段落/评论**：key19=出现间隔整段说明、key21="当可以使用时…"正文段、key22=一条玩家评论留言（"觉醒之树要在哪里额外获取啊？"）。key18 实际正确（引号内中文无假名，前次脚本误报）。
- 修复：key19→"色情指挥官的出现间隔"、key21→"关于操心虫"、key22→"评论区"。
- 教训：**验证必须同时抓「顶部跳转目录锚点链接」与「h2/h3 标题」两套**，不能只看标题。用 HTTP 抓 `localhost:4173` 实际返回比对最准（绕过浏览器缓存争议）。

### 二次翻车（误伤正文）：改目录 key 时把正文 blk/key 错填成"评论区"
- key21/key22 改成标题时，**误把 `blk77`（关于操心虫的正文段落）、`key452`（该段首句）的 zh 填成"评论区"、`key454` 漏译成空** → dist 渲染"关于操心虫"标题下出现 `<p>评论区</p>`，正文消失。
- 根因：key21(目录) 与 blk77/key452(正文) 的 ja 文本不同（key21=ソウシンチュウについて 标题；blk77/key452=使用可能な時… 正文），但都同属"操心虫"语义，批量改时混淆。
- 修复：blk77.zh / key452.zh 还原为正确译文（"可使用该功能时，主界面左上角会出现一个使用按钮…"），key454.zh 补译。

### 三次翻车根因（横向滚动条，最终根治）
- **真凶不是 pre、不是大表、也不是"原站就裹在一起"**：用户指出 ja 原站 rgn-container 只含"初心者用…推荐角色"一块，不含后四块（色情指挥官出现间隔/时刻表/关于操心虫/评论区）。脚本精确配对证实：`data/parsed/ja/awakening.html` 的 rgn 确实不裹这四块（content_1_18~21 pos 全在 rgn 结束后）。
- **根因=历史遗留的脏 template**：`awakening.template.html` 是旧版 ja 解析+旧 build 留下的，当时把后四块错误塞进了一个 rgn-container（ja 解析修好"不裹"之后，template 没重跑 build，一直沿用旧的脏 template）。`i18n build` 读 `data/parsed/ja` 生成 template，ja 干净→新 template 自然干净。
- **修复（根治，非治标）**：`python -m escah_pipeline.cli i18n build --pages awakening` 重生成 template+JSON → 新 template 的 rgn 不再裹四块（与 ja 对齐）；已修译文经 memory 回贴完整保留（blk77/key452 等）。再 sync-site→build→重启 preview，dist 实测四块已移出 rgn。
- **已撤掉治标 CSS**：曾临时加 `.mirror-content .rgn-container{overflow-x:clip}`，根因治后删除（避免误裁正常内容）。pre 折行 CSS 保留。
- **铁律：配对 div 必须用嵌套计数算法**（`re.finditer(r'<div\b|</div>')` + depth），`nearest-open-before` 算法会误判包裹关系（曾因此误以为"ja 原站也裹四块"）。验证 rgn 包裹必须跑精确配对脚本，不可肉眼看"nearest rgn before"。
