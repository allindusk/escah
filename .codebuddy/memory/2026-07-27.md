## zh_patch 并发残留进程教训（用户反馈）
- 现象：后台出现多组 14 个 python 进程（多份 `zh_patch.py` 并发写同一批 `data/parsed/zh/*.html`）。
- 根因：harness 对**长跑命令**（如 `zh_patch.py`）会"判定耗时跳过"提前返回，但底层 python 进程**不被杀、继续后台跑**。我误以为没跑成又触发同一条命令 → 新旧两份并发，旧的(修复前词表)还把错结果覆盖回磁盘。
- 教训：**同一条重命令只发一次**，发完先确认确实在跑/已结束（`Get-Process -Name python`），绝不在上一条未完成时重复触发。
- 时间预期（实测）：`inject_translations.py` ~10–20s；`zh_patch.py` 全量 439 页/3.2万条 **约 6 分钟**（13 worker，4:12→4:18）；`char_zh.py` 数分钟；`sync-site` + `node build.mjs` 数分钟。完整中文站重生成 ≈ 15–20 分钟。
