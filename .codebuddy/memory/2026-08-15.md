## 含角色名 span 的块误回退日文（系统性 bug，已修复）
- **现象**：用户报 raid-formations.html 某段（含角色名浮窗）整段露日文。根因是渲染引擎 `render_locale` 的块级回退逻辑：含无-img 角色名 span（data-char/char-ref/plugin-tooltip）的块会被强制走「节点级渲染」（continue），以保留角色名原位与浮窗。但若该块的**节点级 key 缺译**、而**整段 blk.zh 完整**，节点级渲染对缺译 key 兜底显示日文 → 整段露日文（即使整段译文早已翻好）。
- **修复**（pipeline/escah_pipeline/i18n.py，render_locale 块级回退的 char-span 分支）：
  - 节点级全译 → 维持原位内联 char-ref（行为不变，b-universe 等无回归）。
  - 节点级有缺译 **但** blk.zh 完整 → 用 blk.zh 作正文、句末补【角色名】浮窗（display 名走 `_disp_name`→names.yaml 权威译名），消除日文回退。
  - blk.zh 也空 → 仍走节点级（日文兜底，不可避免）。
- **范围（源级扫描，json 块在 `_blocks` 子键下）**：受此 bug 影响的含角色名 span 块共 **3448 处**（跨约 110 页，bedroom-scenes 407 / unique-effects 396 / skills 328 / gacha 268 … raid-formations 118 等）；**0 处** blk.zh 为空（即全部可修复）。已随本次改动全站修复。
- **验证**：`render_locale('raid-formations','zh')` blk47 可见文本假名 0；`sync-site` + `build.mjs build` 后 `dist/zh/raid-formations.html` 同段中文完整、角色名内联 + 句末 `【节拍护符·诺诺诺】` 浮窗正常。b-universe char-ref 仍内联（无回归）。
- **版本**：1.2.6→**1.2.7**，changelog 加用户视角条目。已本地提交 `5f8a6b6`（未 push，待用户指令）。
- ⚠️ 经验：i18n JSON 块在 `d["_blocks"]` 子键（非顶层），扫描脚本必须 `d.get("_blocks", d)` 否则取不到块（此前扫描全 0 即此因）。`keyN` 仍在顶层。

## 角色浮窗/档案页「人物档案」模块缺失（已修复 + 全站自查）

- **影响范围（全站自查）**：缺 `プロフィール` 的角色共 **2 个**——`エスカアメイズ・ファンタスマ`（超昂阿梅兹·幻梦）、`レジェンド・エスカレイヤー`（传说·阿梅兹蕾雅）。已用修复后提取器重提 `プロフィール` 模块并 merge 回原 JSON（保留其他 section 既有 zh），再 `sync-site` + `build` 生效。

## 内联角色头像浮窗指向错误角色（已修复 + 全站排查）
- **现象**：用户报 raid-buff-debuff 页表格里头像 img（实为バレンタインマドカ 头像，alt/title=`バレンタインマドカ_icon.png`）被包在 `<span data-char="エスカアメイズ・ファンタスマ">` 里 → 浮窗显示成超昂阿梅兹·幻梦。这是**源站数据错位**（头像图片与外层 data-char 角色名不符）。
- **根因**：`site/.vitepress/theme/components/MirrorContent.vue` 的 `tagAvatars()` 对「已在 [data-char] 祖先内」的 img 直接 `return` 跳过（line 94 旧逻辑），导致其内置的 alt/title 兜底解析（能正确得出バレンタインマドカ）被压制，错误外层 data-char 胜出。
- **修复**：抽出 `resolveAvatarName(img)`（avatarMap 优先、alt/title 兜底）。当 img 在 [data-char] 祖先内、且解析出的真实角色与祖先 data-char 不同、且**该祖先 span 仅含此 img（无角色名文本）**时，以图片真实角色覆盖祖先 data-char；含真实角色名文本的标签（如 artists 页插画索引）不动，避免误改。
- **全站排查**：脚本扫 `dist/zh/*.html` 得 **6 处** data-char 与 img 不符；其中 5 处为 IMGONLY（纯头像 span，含用户报的 raid-buff-debuff + character-exchange×2 + scenario-order×2）已被修复覆盖；1 处 artists 页 `リバースバニー・ヤブルー` span 含文本「魔女ヤブルー」（插画索引，img 与名本就不同角色），按规则保留不覆盖。
- **版本**：1.2.8→**1.2.9**，changelog 加用户视角条目。改动未 push（待用户指令）。
- ⚠️ 临时脚本（_scan_avatar_mismatch.py / _avatar_mismatch.txt）已用完即删。
- ⚠️ 经验：头像浮窗的 data-char 优先级应为「图片自身归属 > 外层包装 data-char」，不要因"已在角色容器内"就跳过图片的真实身份解析。
