## 角色浮窗「盖住鼠标」根因修复（第 N 次，这次找到真因）

**症状**：`npm run dev` 实测浮窗仍与鼠标重叠，之前多次改 `placeHover` 都没根治。

**真因（两个，之前只盯着水平方向）**：
1. **只算了水平、没校验垂直**：`placeHover` 旧逻辑只在水平方向挑「锚点↔鼠标间隙」，
   而 `top = min(a.top, my) - 4`，浮窗 `max-height: 94vh` 极高 → 鼠标几乎必然落在浮窗
   纵向区间内。只要水平兜底把浮窗放到 `mx` 附近就会盖住光标。
   「不盖鼠标」是分支顺序的**副产物**而非被校验的约束。
2. **鼠标坐标会过期**：`mouseover` 只在**进入元素时触发一次**，锚点大（宽表格单元格、
   大图）时鼠标在其内部移动，`mx/my` 仍是入口坐标 → 按旧坐标摆放又压住光标。

**修复**：
- `CharHoverModal.vue::placeHover` 重写为「先选边 → 再显式校验」：
  ① 水平选 `spaceLeft`/`spaceRight` 中放得下且更宽敞的一侧，使浮窗整体位于鼠标一侧；
  ② 垂直照旧贴锚点/鼠标顶部并夹回视口；
  ③ **兜底校验**：若 `(mx,my)` 仍落在浮窗矩形（含 gap 外扩）内，则把浮窗推到鼠标
     下方 / 上方；上下都塞不下才强行水平让开。gap 10→12。
- `MirrorContent.vue` 新增 `onMove`（挂 document `mousemove`，onUnmounted 解绑）：
  鼠标在同一锚点内移动时刷新光标坐标。
- `charModalStore.ts` 新增 `updateHoverPointer(mx,my)`：`this.anchor = {...this.anchor, mx, my}`
  —— 换新对象故已有的 `watch(() => store.anchor)` 会自动重跑 `placeHover`，无需额外接线。

**验证**：`read_lints` 干净；`node build.mjs build` 通过（stderr 只是 PowerShell 把进度
输出当错误 + 既有的 chunk >500kB 警告）。

**教训**：用户已明确说过这是「很容易写」的需求却反复改不好，原因是每次只补水平分支、
没把「鼠标不在浮窗内」写成可校验的不变式。此类几何约束应**先写校验、再写启发式**。

## 角色头像点击放大+玻璃遮罩 bug（已修复，根因在 Layout.vue）
- 现象：list-r 等页点表格里角色头像「固定浮窗」时，头像同时被灯箱放大并盖上 `.lightbox-mask` 玻璃遮罩。
- 根因：`Layout.vue` 的 `onDocClick`（图片灯箱）与 `MirrorContent.vue` 的 `onClick`（pin 浮窗）都挂在 `document` 的 `click` 上。`MirrorContent` 里 `e.stopPropagation()` 只能阻止冒泡到祖先元素，**无法阻止同元素（document）上另一个监听器**触发，故灯箱仍被打开。`onDocClick` 原对所有 `.mirror-content img` 开灯箱，未排除带 `data-char` 的头像。
- 修复：`onDocClick` 增加 `if (img.hasAttribute('data-char')) return`，角色头像交由 pin 逻辑独占。一次性解决全站所有含头像的页面（list-r/ssr/sr/npc、角色页、正文内联头像等），无需逐页改。
- 注：构建必须从 `site/` 目录跑 `node build.mjs build`；从仓库根跑会因 README.md 被当入口导致 `Rollup failed to resolve import "vue/server-renderer"` 失败（环境配置问题，与代码无关）。
