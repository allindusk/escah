## 角色浮窗失效根因 3（带 g 正则共享 lastIndex）— 2026-08-13 晚
- **根因**：`collectBlockCharTags` 的 walker 判定阶段用 `nameRegex.test()`，而 `nameRegex` 是带 `g`（global）标志的正则。`upgradeTooltipCharNames`（在 collectBlockCharTags 之前跑）对同一 `nameRegex` 调 `exec` 会把 `lastIndex` 留在某个角色名末尾；随后 walker 跨多个文本节点复用同一个 `nameRegex.test()`，每次从残留 `lastIndex` 起算，导致从某点开始整批纯文本块里的角色名被漏判（不进 hits）→ 不包 char-ref → 浮窗失效。实测 b-universe 约 11+ 个裸 `<span>名字</span>`（时间停止/必杀技节整段、坦克节 noexists 神骑伊芙、诅咒节 plugin-tooltip 魔女雅布鲁等）全失效。
- **修复**：新增无 g 副本 `nameRegexTest = new RegExp(plainDisplays.join('|'))`，把 `collectBlockCharTags` 的 acceptNode 判定（`nameRegex.test`→`nameRegexTest.test`）与 `upgradeTooltipCharNames` 的 `nameRegex.test`→`nameRegexTest.test` 全部改用无 g 版本；`nameRegex`（带 g）仅保留给块内 `exec` 包裹阶段（每次循环已 `lastIndex=0` 重置，安全）。
- **验证**：python 复现脚本确认原 BUGGY 漏判 `四猎斧泽布利艾尔`/`节拍婚礼·千麻`（正是用户报告的两例），FIXED 全部命中。已重新 build（清 .vitepress/cache）+ 重启 preview @4173。用户需 Ctrl+F5 硬刷核对。

## 角色浮窗失效根因 4（纯角色名文本节点被 parts.length<=1 误跳过）— 同日晚
- **现象**：蓝字（plugin-tooltip）修好后，仍有约 5 个**裸 `<span>纯角色名</span>`**（如 `节拍婚礼·千麻`、`神骑伊芙` noexists、`一神键阿兹艾尔`、`神骑维阿尔`、`翼龙剑圣茜`）无浮窗。带前后缀的（`四猎斧泽布利艾尔5秒`、`圆香·突击（...）` 等）正常。

  1. 页面 raw 放 `data/raw/<page_filename(name)>.html`（`page_filename` 用 `quote(name, safe="")` → **URL 编码文件名**，不是日文原名！如 `公式ヘルプ`→`%E5%85%AC%E5%BC%8F%E3%83%98%E3%83%AB%E3%83%97.html`）。这是前期最大坑：我误用日文原名当文件名，parse 找不到 raw。
  2. 注册：`data/registry/pages.yaml` 追加 `{name, slug, category, mode}`。外部源（非 wikiru）页面**不走 `discover`**（会 fetch wikiru 失败），直接写 pages.yaml。
  3. `parse`（或单进程 `_parse_official_help.py`，因 Windows 多进程 spawn + PowerShell 中文 argv 乱码，CLI `parse --pages 公式ヘルプ` 会匹配失败）→ 生成 `data/parsed/ja/<slug>.html` + `<slug>.chunks.json`。
  4. `i18n build --pages <slug>` → `data/parsed/i18n/<slug>.template.html` + `<slug>.json`（zh 空）。
  5. `i18n extract --pages <slug>` → `tools/_todo_translate/new_translation_<日期>.txt`（含 `# MAP X=<slug>` 段 + `[N] 日文`），用户翻译后写同目录 `_translated.txt` → `i18n fill` 回填。
  6. `sync-site` 生成 `site/<ja|zh>/<slug>.md`；`config.ts` nav 已指向 `/<locale>/<slug>.html`。
